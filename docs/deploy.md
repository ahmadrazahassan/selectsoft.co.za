# Deploying Select Soft

## Why Vercel returns 404

This site is not a Vercel application. It is built by `vinext` through the
Cloudflare Vite plugin, and the build output is a **Cloudflare Worker**:

```
dist/server/index.js      the Worker
dist/server/wrangler.json its generated config
dist/client/              581 static assets
```

There is no `index.html` at the output root and no serverless function Vercel
recognises, so Vercel serves nothing and every route answers `404: NOT_FOUND`.
The Worker also expects Cloudflare bindings, `env.ASSETS` and `env.IMAGES`,
which do not exist on Vercel at all.

Deleting the Vercel project is the tidiest fix. Nothing about this codebase can
run there without replacing the runtime.

## Deploying to Cloudflare Workers

```bash
npx wrangler login
npm run deploy
```

`npm run deploy` builds and then runs
`wrangler deploy -c dist/server/wrangler.json`. The config is generated by the
build, so there is no `wrangler.toml` to maintain by hand. Confirm a build
before deploying with:

```bash
npx wrangler deploy --dry-run -c dist/server/wrangler.json
```

That should report the Worker name `selectsoft` and two bindings:

```
env.IMAGES         Images
env.ASSETS         Assets
```

If it says **No bindings found**, the Worker will serve pages but fail on
`/_next/image`. The bindings are declared in `vite.config.ts` under
`localBindingConfig`, not in the generated file, so fix them there.

## Environment variables

Two kinds, and the difference matters.

**Build time.** Anything beginning `NEXT_PUBLIC_` is inlined by Vite when you
build, so it must be set before `npm run build`, not on the Worker:

```bash
NEXT_PUBLIC_SITE_URL=https://selectsoft.co.za
NEXT_PUBLIC_SUPABASE_URL=https://<project>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<publishable key>
```

`NEXT_PUBLIC_SITE_URL` drives canonical URLs, the sitemap and the structured
data. If it is wrong at build time the deployed site advertises the wrong
domain. The fallback in `app/config/site.ts` is already the live domain, so a
plain build is correct, but set it explicitly in CI.

**Runtime.** The service role key is read inside the API routes and must be a
Worker secret. It must never be committed or given a `NEXT_PUBLIC_` prefix:

```bash
npx wrangler secret put SUPABASE_SERVICE_ROLE_KEY
```

Until that is set, the contact and newsletter routes answer 503 and tell the
reader to email instead. See `docs/forms-setup.md`.

## Pointing the domain at the Worker

After the first successful deploy, in the Cloudflare dashboard:

1. Add `selectsoft.co.za` as a zone and move the nameservers at your registrar.
2. Under the `selectsoft` Worker, add custom domains for `selectsoft.co.za`
   and `www.selectsoft.co.za`.

Cloudflare issues the certificate. Do not add a proxy record by hand; the
custom domain binding does the routing.

## After deploying, check these

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://selectsoft.co.za/
curl -s https://selectsoft.co.za/robots.txt
curl -s https://selectsoft.co.za/sitemap.xml | head -5
```

The sitemap should list `https://selectsoft.co.za`, not localhost and not the
old domain. Then load a review page and confirm a product image renders, which
is what proves the `IMAGES` binding is working.
